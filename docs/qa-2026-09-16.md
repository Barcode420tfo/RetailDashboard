## Repairs

- Validate database URI shape, port, proxy hop count and production origin/cookie
  settings before connecting or running startup database work.
- Report startup failures without dumping driver errors or connection strings.
- Exclude health checks from the user request rate limit; honor the configured
  port in Docker's health check and bound its fetch time.
- Return safe JSON for malformed/oversized bodies and preserve unavailable-service
  status. Delegate errors when HTTP headers have already been sent.
- Omit headers/query strings from request logs, reduce successful-request noise,
  and avoid logging raw parser error bodies. A submitted password marker did not
  appear in the smoke-test logs.
- Filter non-model exports out of database index creation/verification scripts.
- Archive and clear the local MongoDB log. Archive is private under
  `.local/log-archives/`; database files were not removed.

## Repeating checks

```sh
npm test
npm run build
npm audit
npm run test:db
node --env-file=.env server/scripts/smoke-production.js
```

The production smoke script connects to the configured database and runs normal
startup initialization (including authentication indexes/administration lock).
It does not create test accounts or business records. It requires Chrome or
Playwright Chromium and an unused local port (default 3307, override SMOKE_PORT).
The database verification command tests duplicate rejection inside an aborted
transaction and verifies no test record remains.

## Remaining limits

  not accessible here. These local code changes have not been deployed.
- Docker was unavailable; the container image was not built or run.
- No authenticated browser login, upload, account recovery or destructive edit
  flow was performed against real accounts. Automated tests cover selected
  calculations and authorization rules, not every end-to-end business flow.
- Rotate the previously exposed Atlas password in Atlas, local .env and Railway.
